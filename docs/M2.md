# Milestone 2 — Android foundation, Compose shell, JNI handshake

Status: **implemented; final device verification in progress.**

## What M2 delivers

- Android application skeleton with `minSdk 31`, `targetSdk 36`, `compileSdk 37`.
  - `targetSdk 36` satisfies the Google Play requirement recorded in `docs/ARCHITECTURE.md`.
  - `compileSdk 37` is required by the selected 2026 AndroidX/Compose release; this does not change the Play target.
- Jetpack Compose shell:
  - compact phone navigation bar and expanded tablet navigation rail;
  - project/workspace bar;
  - dominant editor region;
  - bottom terminal panel with drag-resizable divider;
  - session chips with add/close and a Stop All action;
  - programming toolbar with the requested key set.
- Foreground service skeleton with notification channel and ongoing notification.
- Real Rust `cdylib` (`libforgebox_core.so`) built by `cargo-ndk` for ARM64 and x86_64 and loaded from Kotlin via JNI.
- Narrow `ForgeNative` façade with version and echo handshake methods.
- Pure Kotlin layout policy unit tests and pure Rust greeting tests.

## Explicit non-goals for M2

These are placeholders by design and are **not** claimed complete:

- no real file explorer or SAF import/export (M4);
- no code editor widget (M5);
- no PTY, shell, terminal rendering, or real sessions (M6/M7);
- no policy engine, checkpoints, Git, agents, or network broker (M8+).

The M2 terminal and session chips are UI structure only. They do not execute commands and must not be presented as a working terminal.

## Build and test commands

From the repository root on Windows:

```powershell
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
$env:ANDROID_NDK_HOME = "$env:ANDROID_HOME\ndk\27.1.12297006"

cargo test --manifest-path rust/forgebox_core/Cargo.toml
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest --no-daemon
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n dev.forgebox.app/.MainActivity
```

## Verification log

- Rust unit tests: pass (`2 passed`, `0 failed`).
- Gradle unit tests: pass (`2 tests`, `0 failures`).
- Debug APK: builds with `libforgebox_core.so` packaged for `arm64-v8a` and `x86_64`.
- `packaging.jniLibs.useLegacyPackaging = true` is set so AGP extracts native libraries to `nativeLibraryDir` with executable permissions. This preserves the M12 W^X-safe execution path without using the deprecated manifest attribute.
- Manifest: `minSdk 31`, `targetSdk 36`, `compileSdk 37`.
- API 31 emulator (`emulator-5580`, x86_64): app starts, activity is displayed, no `FATAL`, no `UnsatisfiedLinkError`, no `NoSuchMethodError`.
- On-device UI hierarchy confirms: project bar, editor placeholder with live JNI echo, bottom terminal panel, session chip, `+` control, cwd label, Close session button, programming toolbar, top-bar Stop All / terminal toggle, and compact bottom navigation.
- Interaction smoke tests on API 31: adding a session creates `session-2`; tapping Search switches the project bar to `Project / Search`; terminal toggle hides the terminal; Stop All removes the extra session.
- Foreground service: `dumpsys activity services` reports `dev.forgebox.app/.service.SessionService` with `isForeground=true`, notification id `1001`.
- Native library extraction: `/data/app/.../lib/x86_64/libforgebox_core.so` exists and is executable.
- Attached LDPlayer image: Android 9 / API 28 / x86_64. It is **below the declared minimum** and crashes in AndroidX startup because `android.os.Trace.isEnabled()` is absent. This is an unsupported test device, not an app regression.

## Security review

- No `INTERNET` permission is declared in M2.
- No `MANAGE_EXTERNAL_STORAGE` permission is declared.
- The app sets `allowBackup="false"`.
- The native library is loaded from the signed APK; no executable is written to or run from the writable app directory.
- No credentials, project data, or logs are handled in M2.
- Remaining risk: the foreground service is a skeleton; its lifecycle and lifecycle-driven session cleanup must be reviewed again in M7.

## Known limitations

- The JNI handshake uses strings, not the final protobuf façade. That is intentional for M2 and will be replaced in M3.
- The UI contains placeholders for editor and terminal content.
- Live processes are not created in M2.
- The x86_64 emulator validates layout and JNI loading only; ARM64 device testing remains required for execution-related milestones.
