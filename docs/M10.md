# M10 — Linux Userspace Environment (PRoot + Rootfs)

## Scope
- Proto Linux userspace surface: Linux env status/install/uninstall, shell spawn, package install convenience, run installed binary, and install progress event.
- Rust `linux_env` module for cache/state management under `ForgeBox/Cache/linux/` (not `Projects/`), distro/rootfs status, install state transitions, uninstall, package/binary validation, and CWD mapping helper.
- M8 policy extension: `CommandOrigin::{USER,INSTALLED_BINARY}`. Installed binaries require CONFIRM through existing M8 approval token flow. Package installs remain USER-origin and are ALLOW unless existing M8 rules apply.
- Audit records added/used for `linux_env_install`, `linux_env_uninstall`, and `installed_binary_run`.
- Kotlin Linux env model/repository/viewmodel and basic Linux env dialog in Project Explorer. Terminal has Bionic/Linux shell kind selector; Linux shell spawn uses Rust `LinuxShellSpawn` request.
- Package install convenience is a PTY shortcut (`npm install -g ...` / `apt-get install -y ...` / `apk add ...`) spawned as a normal terminal command. No background package manager.

## Reordering / Cancelled Scope
This M10 supersedes the old draft M10. **Cancelled / not built:** built-in OpenAI agent, agent tool gateway, agent state machine, provider config store, agent approval UI, agent upload consent sheet, built-in OpenAI HTTP client, built-in SSH client, built-in local desktop agent launcher. Agents are user-installed via terminal; tools do their own auth.

Cancelled agent proto messages were checked and **none were present/added**. The only agent-related field remains existing `EvaluateCommandRequest.actor_is_agent` from M8 policy evaluation.

## Non-goals
- No built-in agent runtime, agent gateway, provider config store, agent UI, OpenAI/SSH/local desktop agent clients.
- No seccomp validation claim on supported device; seccomp remains default off/disabled for guest compatibility.
- No Bionic runtime pack in M10.
- No background package manager/install service.
- No VFS bypass for workspace app reads/writes; app-side file operations still go through VFS.

## Option B / Runtime Verification
**No emulator runtime verification on a supported device; only API 28 emulator available (below minSdk 31).**

Runtime-only claims in this milestone are **not runtime-verified** for that exact reason. This includes: actual PRoot/rootfs bootstrap/install on device, Codex/OpenCode install/run on device, Linux shell PTY behavior under PRoot on device, seccomp behavior in guest, and package install end-to-end on device.

## Supported-Device Verification Checklist (when available)
1. Install app on supported device (API >= minSdk 31).
2. Open Project Explorer > Linux, install Alpine or Debian rootfs. Confirm progress events, final READY state, and cache path under `ForgeBox/Cache/linux/`.
3. Open Terminal, select Linux shell, confirm shell spawns in project CWD with same absolute path mapping inside guest.
4. Run `node -v`/`npm -v` (or install required packages) inside guest.
5. Install Codex: `npm install -g @mmmbuto/codex-cli-termux` and run `codex --version` / basic prompt.
6. Install OpenCode: `npm install -g opencode-ai` and run `opencode --version` / basic prompt.
7. Verify installed-binary execution prompts CONFIRM via M8 approval flow and audit records `installed_binary_run` are redacted.
8. Verify uninstall removes `ForgeBox/Cache/linux/` rootfs/cache and status returns NOT_INSTALLED.
9. Verify app-side reads/writes still use VFS; guest shell file ops are OS-level by design.

## Security / Compatibility Statements
- Same-UID is not a security boundary.
- PRoot is a compatibility layer, not a sandbox.
- UI/docs state: "This installs a Linux compatibility environment. It is not a security sandbox."
- `INSTALLED_BINARY` CONFIRM warning is honesty, not a safety guarantee.
- Seccomp remains default off/disabled for guest; not validated on supported device.
- PRoot uses ptrace; network control falls back to M11 per-session toggle.

## Limitations
- Linux install/spawn/package install/Codex/OpenCode execution are **not runtime-verified** on a supported device due to Option B (API 28 emulator below minSdk 31).
- Current Rust install handler records a not-runtime-verified failure/progress result on this host; real device bootstrap requires supported-device validation and may need runtime-specific PRoot/rootfs fetch/extract implementation.
- Package install convenience uses a PTY command shortcut; it is not a robust package manager and has no background job management.
- Guest shell reads/writes are OS-level and bypass VFS by design; this is documented and consistent with M6/M7 terminal behavior.
- M8 `#[cfg(unix)]` supervisor tests remain execution-unverified on this Windows host (WSL/Docker unavailable).
