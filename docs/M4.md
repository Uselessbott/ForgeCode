# M4 — Private Workspace and Project Explorer

## Status

**Complete for M4 scope.** No editor, no terminal/PTY, no git UI, no agents, no networking, no SAF flows.

## Deliverables

- **Proto/Rust contract extensions** (`app/src/main/proto/forgebox.proto`, `rust/forgebox_core`):
  - Added `RenameFile`, `DeletePath(recursive)`, `CreateFolder`, `DeleteProject`, `RenameProject`.
  - `ListFiles` supports `recursive` for flattened explorer tree.
  - `Project` includes `storage_bytes` (summed from `files_index`).
  - Rust handlers validate project IDs and paths through existing VFS; reject traversal/absolute/backslash/NUL/control/empty segments; reject symlinks in existing components/final target; reject project-root delete/rename as path ops; reject non-recursive delete of non-empty directory.
  - DB index maintenance added for delete/rename prefix re-keying and project rename/delete.
- **Kotlin data/ViewModel layer**:
  - `ForgeBoxCore` transport seam + `ForgeBoxRuntime : ForgeBoxCore`.
  - `WorkspaceRepository` wraps all workspace operations via `ForgeBoxRuntime.call()` only; maps proto status/error to `Result` failures.
  - `ProjectListViewModel` and `ProjectExplorerViewModel` expose loading/data/error/actionError state, use `Dispatchers.IO`, no Android Context.
- **Compose UI**:
  - `ProjectListScreen`: project list with name/created/storage/path, FAB create dialog, long-press rename/delete with confirmation, tap opens explorer.
  - `ProjectExplorerScreen`: project-relative flattened tree, refresh, create file/folder, long-press rename/delete/copy path, recursive folder delete confirmation, file tap reads via `ReadFile` and shows text preview for small printable files; otherwise "Preview not available in M4".
  - `ForgeBoxApp` now routes list ↔ explorer; M3 core status retained.

## Security review

- **Actual path validation boundary**: Rust VFS/runtime. Kotlin never reads/writes/renames/deletes ForgeBox workspace files directly; it only calls `ForgeBoxRuntime.call()` protobuf requests.
- **Kotlin checks**: defense-in-depth only (basic non-blank UI enablement, confirmation dialogs). Kotlin does not replace Rust validation.
- **VFS rules enforced in Rust**: conservative project names; project-relative paths only; rejects `..`, absolute, backslash, NUL/control, empty file path; canonical root resolution; symlink components rejected; final symlink rejected for create/rename targets; delete rejects symlink targets; project root cannot be deleted by `DeletePath`; non-empty directory requires `recursive=true`.
- **Destructive UX**: delete dialogs name the target; folder delete states recursive delete; project delete states M13 checkpoint not yet available. Rust still enforces rules regardless of UI.
- **Internal paths**: `internal/{db,audit,checkpoints,journal,secrets}` are outside `ForgeBox/Projects` and are never listed/requested by explorer UI. Explorer only issues project-scoped requests.
- **Not yet protected / known gaps**: no checkpoint/undo before delete (M13); no SAF boundary checks (M11); no archive extraction/quarantine (M11); no per-file secret encryption (M11/M14); no file locking/conflict strategy for future editor (M5); storage usage is based on indexed file sizes, not full recursive filesystem accounting for unindexed files.

## Limitations / follow-ups

- Explorer uses a flattened recursive list, not a lazy-expand tree; acceptable for M4, may need virtualization/tree state in later milestones.
- File preview is text-only, 64KB cap, simple printable check; binary/large files show placeholder.
- Project rename/delete are implemented in Rust/proto/repo/UI; they are destructive operations without M13 checkpoints.
- `ForgeBoxRuntime` remains process-local singleton; M7 moves lifecycle ownership.
- No emulator smoke test was run in this pass; build/unit tests passed.
