# Milestone 6 — Integrated terminal (single stock-shell PTY session)

## Scope delivered

- **Real PTY session**: Rust `pty.rs` spawns `/system/bin/sh -i` (fallback `/bin/sh`) over a Bionic PTY (`openpty`, `fork`, `setsid`, `TIOCSCTTY`, `dup2`, `execv`).
- **Terminal emulation/state**: Rust `terminal.rs` uses `vte` to maintain a simple terminal screen model and emits UTF-8 JSON screen diffs as `TerminalOutputEvent` through the existing `pollEvents` path.
- **JNI/PTY contract**: Added singleton JNI methods `nativePtyOpen/Write/Resize/Signal/Close` in `ForgeNative`/Rust `lib.rs`. The protobuf request/response `call` envelope is unchanged; terminal output/lifecycle uses new event kinds in `forgebox.proto`.
- **Foreground service ownership**: `SessionService` owns M6 single-session foreground lifetime, notification actions (Stop terminal / End all), and a partial wake lock while terminal is opened. Rust runtime remains the process-wide singleton per M1 §3.1.
- **Compose terminal panel**: `TerminalPanel` renders terminal state on `Canvas` with `TextMeasurer`, provides IME capture via hidden `BasicTextField`, toolbar keys (ESC/TAB/CTRL+C/CTRL+D/CTRL+Z), Stop/End controls, and disabled “+ M7” affordance. `EditorScreen` toggles a resizable bottom panel.
- **Shared editor/terminal conflict UX**: editor polls active file mtime while terminal is open; clean tabs auto-reload on disk change, dirty tabs get explicit conflict banner with Reload disk / Overwrite disk. No silent overwrite of dirty editor state.

## Required security statement

Shell processes run in the same Android app UID as ForgeBox. This is not a security boundary; PRoot (added later) is a compatibility layer, not a sandbox.

## Constraints / behavior

- Single PTY session only; no multi-session UI, no persistence across app kill.
- CWD validation: PTY cwd is resolved through VFS/canonicalized workspace boundaries and must be under `ForgeBox/Projects/<id>` or ForgeBox root.
- Environment scrubbing: child env is cleared and rebuilt with `HOME=<cwd>/.forgebox-home`, `PATH=/system/bin:/system/xbin`, `TERM=xterm-256color`, `LANG=C.UTF-8`, `TMPDIR=<workspace>/Temporary`, `PWD=<cwd>`.
- Basic limits: sets `RLIMIT_NPROC`, `RLIMIT_CPU`, `RLIMIT_FSIZE` in child (M6 foundation; not a full policy engine).
- Stop semantics: UI Stop sends SIGTERM (`ptySignal(15)`). Service End all / close closes PTY with SIGTERM grace then SIGKILL.
- No policy engine, seccomp, checkpoints, destructive-op confirmation, git UI, agents, networking, runtime packs, or PRoot in M6.

## Known limitations

- Terminal emulation is minimal `vte` screen-state for M6; not full xterm behavior (scrollback/history, selection/copy UI, alternate screen richness, full SGR styling) is limited.
- Terminal output is polled via `pollEvents`; terminal controller consumes polled events. Single-session M6 design avoids complex event routing but event bus should be formalized for M7+.
- Android 12+ phantom process killer may still terminate child processes; FGS/wake lock improves liveness but is not a guarantee.
- No emulator/device smoke test was run in this environment.
- Rust PTY spawn/read/close tests are `#[cfg(unix)]`; Windows host runs non-PTY Rust tests and Kotlin JVM tests.
