## Event model
M7 uses a **blocking poll with timeout** via `nativePollEventsTimeout(handle, max, timeoutMs)`. Kotlin `TerminalSessionController` polls on a background coroutine with `timeoutMs=250`, so idle sessions do not busy-loop and active output wakes promptly via Rust `events_cv`. `nativePollEvents` remains for compatibility. This satisfies M1 §3.2 blocking-poll option. Rationale: simple, no JNI callback/env attachment from Rust reader threads, bounded wakeups for N small sessions.

## Coalescing/backpressure
Per PTY reader thread coalesces output with 16ms/64KiB targets (`TERMINAL_OUTPUT_COALESCE_MS`, `TERMINAL_OUTPUT_COALESCE_BYTES`). If pending output exceeds `4 * 64KiB` before flush, incoming bytes are dropped for that session and a visible `[ForgeBox: N bytes dropped]` notice is injected into terminal state. No unbounded cross-session buffering. Bounded scrollback: 10,000 lines per session.

Memory ceiling justification: 3 high-rate sessions * (10,000-line scrollback ring + 24 visible rows + coalescing buffer capped at 256KiB before drop) + bounded event queue drained by poller. Rust test `three_high_rate_sessions_coalesce_and_bound_memory` asserts scrollback/total-lines bounds, queue drain, and drop notice.

## Session model
- Rust `Runtime` owns N PTY handles in one process-local singleton runtime (M1 §3.1).
- Session cap: **6 phones / 12 tablets**. Enforced in Rust (`pty_open` returns `SESSION_CAP_REACHED`) and UI disables `+` when cap reached (`TerminalPanel` uses `canCreate`; shows `cap ${sessionCap}` label). Kotlin computes cap from `smallestScreenWidthDp>=600`.
- Each session has stable `pty_id`, user-visible unique name, cwd, lifecycle state, exit code, timestamps, env overrides (restricted allowlist: TERM/LANG/LC_ALL/LC_CTYPE/COLORTERM).
- `nativePtyOpen` validates cwd under `ForgeBox/Projects/<id>` or ForgeBox root through VFS resolver.
- Stop sends SIGTERM to session process group; Stop All stops every session with confirmation in UI.
- Session metadata persists in SQLite `terminal_sessions`.

## Restore/recreate (A2/T7)
After OS/app kill, live PTY processes are **not** restored. On runtime init, Rust marks previously-running DB rows as restore-available (`was_running` cleared, `previous_process_ended=true`) and emits `TerminalSessionRestoreAvailableEvent` with name/cwd/env_overrides_json/exit metadata. UI shows "previous process ended" and offers recreate. Recreate spawns a fresh shell in same validated cwd and restores name; env overrides are preserved and passed on recreate (`TerminalSessionController.recreateRestorable` passes persisted `envOverridesJson`, default `{}`). **No live scrollback/output replay.** No scrollback snapshot is persisted as live output; restore banner/notice is visually distinct. Verified by `TerminalMultiSessionControllerTest.t6_restoreBannerRestartAndDismiss` and `t7b_restoreRestartKeepsOtherMarkers`.

## FGS/lifecycle and notification (A6)
`SessionService` remains foreground owner while terminal sessions are active/open. Notification content is built by pure `NotificationContentBuilder` (N1, `NotificationContentBuilderTest`: zeroSessionsStopsForeground, oneRunningShowsCountsAndActions, manySessionsAndCapReached, activeExitedFallsBack). Service observes `TerminalSessionController.state` and refreshes notification on state changes including spawn/exit/rename/active switch (N2 wiring; pure builder covers content). When active session count transitions to 0, builder reports `shouldStopForeground`; service releases wake lock, stops foreground, and stops self (N3 wiring; pure builder covers zero-session decision). `onTaskRemoved` stops all sessions, releases wake lock, stops foreground, and stops service (N4). N2/N3 Android instrumentation/fake-OS service tests not added (deferred M7.x).

## Security / platform statements
- Shell processes run in the same Android app UID as ForgeBox. This is not a security boundary; PRoot (added later) is a compatibility layer, not a sandbox (M1 §8.2/§10.2).
- Android 12+ phantom-process killer may still terminate child processes; FGS/wake lock improve liveness but do not guarantee it (M1 §10.7, R-06).

- No runtime packs, no PRoot, no git UI, no agent/network features.
