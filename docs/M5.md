# M5 — Professional Code Editor

## Status

**Complete for the M5 subset implemented here.** No M6+ work (no terminal/PTY/shell/PRoot/LSP server, no agents, no git UI, no networking, no SAF).

## Chosen editor

- **Choice:** `sora-editor` (`io.github.Rosemoe.sora-editor:editor:0.23.5`, `language-textmate:0.23.5`) hosted in Compose via `AndroidView`.
- **Why:** Real editor component (not TextField) with line/selection editing, undo/redo, IME support, search APIs, and mobile-friendly view; LGPL-2.1 acceptable under ForgeBox posture with release review. See `docs/M5-editor-choice.md`.
- **M5 note:** TextMate dependency is included, but full per-language grammar/theme asset packaging is not completed in this milestone; editor opens as plain text with core editing features. Language-specific highlighting/folding/indent packs are deferred to M5.x.

## Deliverables

- **Proto/Rust (minimal):**
  - Added `StatFileRequest/Response` (`size`, `mtime_millis`, `is_text_heuristic`, `exists`).
  - Added `WriteFileIfUnchangedRequest/Response` with `expected_mtime_millis` conflict detection.
  - Added `GetInfoResponse.max_editable_file_bytes` (`1_048_576` / 1 MiB in M5).
  - Rust `stat_file` validates through existing VFS, rejects symlink/non-regular file, returns UTF-8/NUL heuristic.
  - Rust `write_file_if_unchanged` rejects stale mtime with `CONFLICT: ...`, leaves file untouched on conflict, updates file index and emits modified event on success.
  - No VFS validation rules relaxed.

- **Kotlin/Compose:**
  - `WorkspaceRepository` gained `statFile`, `getInfo`, `writeFileIfUnchanged`; all through `ForgeBoxRuntime.call()`.
  - `EditorViewModel`: tab state, load/stat guard, line-ending detection, dirty tracking, save via `WriteFileIfUnchanged` (or create for mtime=0), conflict surface, overwrite-after-conflict explicit action, unsaved-close guard, reload.
  - `EditorScreen`: tab bar with dirty dot and close, save, go-to-line dialog, simple find-next/replace-all dialog, conflict banner with Reload disk / Overwrite disk, read-only/large-file guard screen.
  - `ProjectExplorerScreen` file tap opens editor; long-press action includes “Open in editor”. M4 preview text changed from “Preview not available in M4” to M5 wording for non-editable preview cases.
  - Mobile programming toolbar: scrollable extra keys wired through `EditorToolbarKeyMapper` to editor actions (insert, tab, arrows, home/end, delete, escape); CTRL/ALT/SHIFT are placeholders/no-op in M5.

## Security / integrity review

- **Save path:** Editor save goes `EditorViewModel -> WorkspaceRepository -> ForgeBoxRuntime.call() -> Rust`. No `java.io.File` workspace reads/writes/renames/deletes added for project files.
- **Conflict handling:** `WriteFileIfUnchanged` compares exact `expected_mtime_millis` to current file mtime. On mismatch Rust returns `INVALID_ARGUMENT` with `CONFLICT: file changed on disk (expected ..., found ...)`; file content is not modified. UI shows conflict and requires explicit user choice: Reload disk or Overwrite disk. Overwrite uses explicit write path after confirmation action; it is not silent.
- **Large-file guard:** `GetInfoResponse.max_editable_file_bytes = 1_048_576` (1 MiB). `EditorViewModel` stats file before read; files larger than cap are marked `tooLarge` and not loaded into editor; UI shows guard message.
- **Line endings:** `detectLineEnding` detects CRLF if present else LF on load. `normalizeToLineEnding` normalizes to LF internally then restores original EOL on save. Mixed/CR-only normalized to selected EOL on save.
- **Encoding:** M5 reads bytes as UTF-8 and uses `is_text_heuristic` (NUL/UTF-8 sample check). Non-text/invalid UTF-8 heuristic files are marked not editable/read-only in M5. Full encoding detection/conversion deferred.
- **Editor component security notes:** sora-editor is a native Android View library, no WebView, no remote script execution in used path. No remote grammars/resources loaded. TextMate dependency present but grammar assets not loaded from remote.
- **Not done:** no LSP, no split view, no multi-cursor, no crash recovery/checkpoint-before-save, no autosave debounce, no indexed find-in-files, no formatting, no symbol navigation/rename.

## Limitations

- Editor is plain-text/core editing in this pass; syntax highlighting/folding/auto-indent are not fully configured with language grammar assets.
- Find/replace is simple in-memory string operation; not using editor searcher advanced options.
- Toolbar CTRL/ALT/SHIFT keys are visual/no-op; no chord handling.
- No emulator/UI instrumentation run in this pass; Gradle unit tests and Rust tests pass.
- `ForgeBoxRuntime` remains process-local singleton (M7 concern).
