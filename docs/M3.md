# M3 — Rust Core, Protobuf Façade, Workspace, SQLite, Event Sink

## Status

**Complete for M3 scope.** M4+ features (real explorer UI, editor host, PTY, git, agents, network broker) are not implemented.

## Deliverables

- **Protobuf wire contract**: `app/src/main/proto/forgebox.proto` defines request/response envelopes with echoed IDs, status/error, and M3 operations: `GetInfo`, `CreateProject`, `ListProjects`, `WriteFile`, `ReadFile`, `ListFiles`. Event messages (`FileChangedEvent`, `LogEvent`) are defined for polling.
- **Rust core (`rust/forgebox_core`)**:
  - `build.rs` generates Rust types via `prost-build` + vendored `protoc`.
  - `Runtime` owns workspace layout, SQLite DB, event queue, and request dispatch.
  - Workspace layout created under app data: `ForgeBox/Projects`, `Temporary`, `Imports`, `Exports`, `Backups`, `Cache`, `Config`, `AgentSessions`; internal dirs `internal/db`, `audit`, `checkpoints`, `journal`, `secrets`.
  - SQLite schema: `projects`, `files_index`, `event_log`. Events are persisted to `event_log` and queued for `pollEvents`.
  - VFS validation: conservative project names, project-relative paths only, rejects `..`, absolute paths, backslashes, NUL/control segments, empty file paths; resolves paths under canonical root; rejects symlinks in existing components; rejects final symlink on write.
  - JNI façade: `nativeInit`, `nativeCall`, `nativePollEvents`, `nativeShutdown`, `nativeVersion`. JNI methods catch panics and throw Java exceptions instead of unwinding across JNI.
- **Android/Kotlin**:
  - Protobuf Java Lite generated via `com.google.protobuf` Gradle plugin 0.10.1 / `protoc` 4.36.2 / `protobuf-javalite` 4.36.2.
  - `ForgeNative` is the single JNI boundary; `ForgeBoxRuntime` owns one process-local handle and exposes `call`/`pollEvents`.
  - `MainActivity`/Compose initializes runtime on IO dispatcher and displays core version/project count from `GetInfo`. No M4 file explorer UI yet.

## Non-goals (explicitly not complete)

- File explorer/project tree UI (M4).
- sora-editor integration, tabs, split editor, search/replace (M5).
- Real PTY/shell sessions (M6/M7).
- Git, indexer, agents, networking broker, SAF import/export flows (M8+).
- Full audit/checkpoint policy enforcement beyond event persistence scaffolding.

## Security review

- **Path validation**: rejects traversal, absolute, backslash, NUL/control, and empty file paths; canonicalizes existing roots; symlink components rejected during resolution; final write target symlink rejected.
- **Project names**: restricted to `[A-Za-z0-9._-]`, 1-64 chars, rejects `.`/`..`.
- **SQLite**: parameterized queries; schema created in app-private internal DB path.
- **JNI**: panics caught before crossing JNI boundary; null/invalid handle checks return Java exceptions.
- **Limitations**: no per-file permission model beyond app sandbox; no archive extraction yet; no SAF boundary checks for import/export; no secret encryption/keychain integration in M3; event queue is in-memory plus persisted log but no retention/compaction policy.

## Limitations / follow-ups

- `ForgeBoxRuntime` is process-local singleton; M7 should move ownership/lifecycle behind service-aware session management.
- `pollEvents` is not yet wired into a UI/audit consumer loop.
- File operations are whole-file read/write and not optimized for large files/editor integration.
- No file locking/contention strategy beyond SQLite transactions and simple filesystem writes; M4/M5 must define editor/save conflict behavior.
- Runtime initialization errors are surfaced in UI status but need structured diagnostics in M14.
