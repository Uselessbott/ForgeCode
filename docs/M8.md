## Policy semantics
| Decision | Meaning | Examples |
|---|---|---|
| ALLOW | Execute without confirmation | normal ls/cat/git status; user shell escapes in interactive terminal where classified allowed |
| CONFIRM | Requires explicit UI approval before execution | recursive delete, project delete, bulk overwrite above threshold, git force push/mirror, git reset --hard, history rewrite, hooks/auth changes, sensitive path writes, dangerous tools, agent shell escapes/pipeline-to-interpreter/inline interpreter exec |
| DENY | Blocked; UI shows reason, no approve | agent unknown/unclassifiable command, invalid/expired/mismatched/reused token consumption |

**Bulk overwrite threshold**: heuristic `BULK_OVERWRITE_FILE_COUNT_THRESHOLD = 20` in `policy.rs`. Commands likely affecting more than 20 files (e.g. `sed -i`, `perl -pi`, `xargs rm`, `find . -exec`, `git clean -fd`, wildcard redirect/tee, `rsync -a --delete`) require CONFIRM. Exact count is unknown before execution; heuristic only; enforced in policy classifier.

## CONFIRM classification coverage (M8)
Covered by policy tests: recursive delete (`rm -rf/-r`, `rmdir -p`, `find -delete`, `find -exec rm`), project delete heuristic, bulk overwrite, git force push (`--force`, `--force-with-lease`, `-f`, `--mirror`), git reset --hard, history rewrite (`filter-branch`, `filter-repo`, `git rebase -i` — classified CONFIRM; non-interactive rebase -i is rare but treated conservatively), hooks change (`git config core.hooksPath`, writes/cp/mv/ln under `.git/hooks`), auth setting change (`git config credential.*`, `git config user.email/user.name`, proxy auth config), sensitive path writes (Config/internal/outside project/.. traversal), dangerous tools (`dd`, `mkfs*`, `shred`, `chmod -R`, `chown -R`, `mount/umount`), agent shell escape/metacharacters (`; && || | backtick $( ) <( ) >( )` and pipeline to interpreter). Agent unknown constructs default DENY; agent inline interpreter exec defaults CONFIRM; user unknown constructs are not auto-DENY.

## Token model
- Single-use, <=60s TTL, bound to `command_hash + session_id`.
- Issued only by UI approval flow via `IssueApprovalToken` runtime request; consumed via `ConsumeApprovalToken` before command execution write.
- Tokens are never accepted from command text; agent-embedded token-shaped args do not bypass CONFIRM and random token strings fail consume binding checks.
- Audit stores redacted approval id/token, never raw token value.

## Supervisor limits
- Process-group-as-unit: PTY close sends SIGTERM to process group, 5s grace, then SIGKILL (`pty.rs`).
- `stop_all()` drains live sessions, emits `supervisor_kill` audit per session (`reason=stop_all`), closes handles.
- Runtime drop kills tracked sessions and emits `supervisor_kill` (`reason=runtime_drop`).
- Wall-clock timeout: default 30 minutes (`pty_wall_clock_timeout`), injectable for tests; on timeout emits `supervisor_kill` audit (`reason=timeout`), sends SIGTERM, waits 2s, sends SIGKILL. **Not runtime-verified on supported device**.

## Audit schema
Append-only JSONL records with fields: `ts, actor, op, resolved_paths, before_hash, after_hash, policy_result, approval_id, session_id`.
Record types written/tested: `policy_decision`, `approval_issued`, `approval_consumed`, `approval_denied`, `supervisor_kill`, plus existing workspace mutation ops (`write_file`, `delete_path`, `rename_path`, `write_file_if_unchanged`).
Rotation: 256KB max file, 5 files retained. Redaction: common secret patterns and `aptok_` tokens; tests cover redaction and order preservation.
