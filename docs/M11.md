# M11 — Network broker

## Status

M11 implementation complete in code and host/unit tests. **No emulator runtime verification on a supported device; only API 28 emulator available (below minSdk 31).** Runtime-only claims below are marked not runtime-verified.

## Scope

- Network broker with three modes: `LOCAL_ONLY`, `CONTROLLED`, `TEMPORARY_BROADER`.
- Allowlist + consent flow, per-session toggle fallback, activity log, cancel, audit.
- Reuses M8 policy/audit patterns and M9 credential broker boundary; does not reintroduce agent/LLM provider/SSH config messages.
- PRoot/guest network is not sandboxed; broker governs app-initiated/UI paths and policy decisions.

## Rust net_policy (Layer 2)

`rust/forgebox_core/src/net_policy.rs`:
- Deterministic `decide(mode, destination, actor, session_enabled, now) -> ALLOW|DENY|ASK`; **ASK never returned** by M11 policy (consent is UI/broker concern).
- `LOCAL_ONLY`: allows loopback (`127.0.0.1`, `localhost`, `::1`); denies others with reason `M12 configures SSH endpoints` (SSH hook inert).
- `CONTROLLED`: allowlist hit allows; miss denies with `not in allowlist; switch mode or add entry`.
- `TEMPORARY_BROADER`: allows within duration/scope; on expiry reverts to prior mode (CONTROLLED default).
- Duration cap 3600s, default 900s.
- Per-session toggle: `session_network_enabled=false` returns DENY regardless of mode.
- Audit: every decision writes `op=net_decision`.

Tests: decision matrix, ASK never returned, temporary expiry/revert, per-session override, audit record, SSH hook inert.

## Rust activity log (Layer 3)

`rust/forgebox_core/src/net_activity.rs`:
- Ring buffer (default 1000), in-flight cancel tokens, cancel marks CANCELLED and emits `net_cancel` audit.
- Runtime handlers: mode state/set, allowlist CRUD, consent placeholder, activity list, cancel, session policy, decision.

Tests: record/cancel/audit, ring bounded.

## Kotlin broker (Layer 4)

`app/src/main/java/dev/forgebox/net/NetworkBroker.kt`, `NetworkRepository.kt`:
- Broker checks `networkDecision` via runtime before opening OkHttp socket.
- LOCAL_ONLY/CONTROLLED/TEMPORARY_BROADER enforced by core decision; consent handled in broker/UI for non-allowlisted destinations when `require_consent=true`.
- Per-session toggle calls `networkSessionPolicy`; Rust kills PTY on disable.
- No auth headers/tokens recorded in activity/audit by design; token redaction remains enforced by audit helpers.

Tests: `NetworkBrokerTest` (fake repo + MockWebServer): LOCAL_ONLY blocks, CONTROLLED allowlist allows, consent remember writes allowlist, per-session toggle denies; D2 allowlist add/remove; D4 policy RPC/disable boundary (PTY kill covered by Rust runtime); D5 consent allow-once/remember/deny; D6 auth-header redaction boundary.

## Integration / Semantics

### Item 2 — M9 git remote path (Option B, honest deferral)

- **Option B selected.** Remote git fetch/push is intentionally **not executed in this M11 build**.
- M11 broker is present, but libgit2 transport wiring (custom smart-subtransport or loopback proxy) is **deferred to M11.x/M12**.
- M9/Rust handlers still enforce credential handle/approval checks and return explicit not-runtime-verified messages.
- Policy path remains unit-tested: CONFIRM/approval token consumption for force push/push; credentials from M9 broker boundary. Network call is not executed.
- Docs updated: `docs/M9.md`, this file.

### Item 3 — NETWORK_DOWNLOAD semantics (confirmed)

- Bundled Alpine minirootfs remains **DEFAULT** (offline).
- `NETWORK_DOWNLOAD` is an explicit opt-in path: Kotlin UI fetches Alpine rootfs through `NetworkBroker` (policy/consent/allowlist/audit) to an app-private cache file, then passes that source path to Rust `linux_env_install` for extraction.
- User initiates download; broker policy applies; consent fires for download destination when not allowlisted and `requireConsent=true`.
- Rust rejects empty-source `NETWORK_DOWNLOAD` with explicit not-runtime-verified/error message (download happens app-side, path passed in). Covered by Rust test `linux_env_network_download_without_source_is_rejected`.
- **Not runtime-verified on supported device under Option B (only API 28 emulator available, below minSdk 31).** App-side download path is unit-tested at broker/RPC boundary; no on-device fetch/install verification.

### Other semantics

- Guest `apk`/`npm` inside PRoot: guest sockets are not sandboxed by broker (M1 §10.5). Per-session toggle disables policy and kills PTY; does not guarantee guest network was not used before toggle.

## VpnService rejection (M1 §14)

`VpnService` rejected for per-process filtering in v1: UID/package scoped, requires user consent, cannot distinguish two child processes of ForgeBox.
