## Security / boundary statements
- Same-UID statement: "Shell processes run in the same Android app UID as ForgeBox. This is not a security boundary; PRoot is a compatibility layer, not a sandbox." (M1 A8.2/A10.2).
- Workspace isolation remains a Rust-enforced application boundary, not a kernel boundary (M1 A5/A8.1/A10).
- Git credentials are not stored in Rust, not passed to child process env/argv, and not logged. Kotlin broker stores tokens in Keystore-backed encrypted storage and issues opaque short-lived handles.
- Git hooks path is set to controlled `.forgebox-hooks-empty` on init; hook execution is not trusted as a security boundary.
- Destructive git operations (push/force push) route through M8 CONFIRM policy and single-use approval token consumption before remote push handler proceeds.

## Limitations / not runtime-verified
- No emulator runtime verification on a supported device; only API 28 emulator available (below minSdk 31).
- GitHub device-flow end-to-end, real remote fetch/push network operations, Keystore persistence on-device, and biometric flows are not runtime-verified.
- Remote fetch/push handlers intentionally do not execute network git operations in this M11 build; the M11 network broker is present but libgit2 transport wiring is deferred to M11.x/M12. The policy path (CONFIRM for force push/push, credential broker handle checks) is unit-tested; the network call is not executed and handlers return explicit not-runtime-verified messages.
- M8 unix supervisor tests remain execution-unverified on this Windows host (WSL/Docker unavailable).
